## Operator-supplied inputs versus generated output

The checkpoint tree was generated by an automated agent run. Within it:

* The CUDA kernels (`sha256_device.cu`, `sha256_batch.cu`), the CPU shim, the
  executors (`cuda_execution.py`, `batch_execution.py`, `pipeline_execution.py`),
  the equivalence suites, and the `PIPELINED_POLICY_V1` policy document are the
  generated artifact.
* Operator-supplied inputs to that run were a task specification and a native
  guide/runner. A comparison against the operator-supplied native guide/runner
  found **no distinctive code overlap** — no shared distinctive identifiers,
  structure or phrasing beyond generic CUDA and Python idioms — and no exact
  third-party copy of any checkpoint file was found in the searched trees.

## What this release ships, and what it does not

This release publishes the **minimal redistributable tree**: the CLI, the
hash-pinned checkpoint core, the accepted receipts, the packaging front end,
the tests and the documentation.

The upstream workspace contained a wider research lane — bulk and physical
benchmark drivers, host-ceiling probes, an iteration loop, and their
superseded first-pass receipts and logs. Those files are **not redistributed
in 0.2.0**. They were:

* not imported by any shipped module (verified by an AST import-graph audit of
  the packaged tree — their removal leaves no unresolved local import);
* not required by the CLI, whose `doctor` checks the retained protected
  modules only;
* not required by the runtime contract of the protected executors — with one
  exception, `cpu_shim/`, which is retained because `batch_execution.py`
  compiles `cpu_shim/driver.cpp` as the CPU oracle the GPU path is compared
  against.

The accepted evidence of record is unchanged: `receipts/acceptance.json`,
`receipts/pipeline_ab.json`, `receipts/pipeline_equivalence_cuda.json` and the
dated fresh receipts under `receipts/fresh-2026-10-31/`. Removing the
superseded lane changed no receipt, no pinned digest and no measured value.

## Hash-pinned protected files

Eighteen checkpoint files are hash-pinned by the bundled receipts
(`receipts/pipeline_ab.json` `hashes_before` plus `original_manifest.json`).
They ship **byte-identical** to the working checkpoint. `vret status` re-verifies
them on demand and reports `VERIFIED` only if all eighteen digests match.

Five of those pinned files contain absolute host paths: four reference
`/workspace/artifacts/agent-tooling-blueprints` inside `__main__` blocks and
`cuda_execution.py` carries a `/home/sefi/venvs/...` glob in its NVRTC
discovery pattern. They were deliberately **not**
edited, because editing them would break the pinned digests that the CLI's own
`VERIFIED` state depends on. They are disclosed as a known limitation instead,
and the CLI's script launcher tolerates the missing `/workspace` directory so
the shipped scripts still run from an installed checkpoint.
